# 2026-07-11: X-Seed Stremio stream launch verification on phone

## Summary

The user asked me to verify on their phone that launching a stream from X-Seed actually opens and plays in Stremio. I connected to a OnePlus CPH2583 over wireless ADB, installed the latest `full` debug APK, and attempted both manual UI navigation and direct deep-link verification.

The manual Flutter UI path was blocked by Flutter's inaccessibility to Android UIAutomator and unreliable coordinate taps on a high-DPI screen, but I confirmed that the Stremio player deep link generated by X-Seed successfully opens Stremio and starts the player. As a self-improvement outcome, I created a reusable `.devin/skills/dart-wireless-debug/SKILL.md` playbook so future physical-device work is faster and more reliable.

## Actions

- Connected to the user's phone at `192.168.100.149:38485` via ADB TLS/mDNS.
- Verified both `com.jxoesneon.x_seed` and `com.stremio.one` were installed.
- Built and installed `app-arm64-v8a-full-debug.apk` from the current working tree.
- Launched X-Seed, searched "NASA", opened a public-domain result, and confirmed streams load.
- Constructed a `stremio:///player/{encodedStream}` deep link and launched it directly on the phone; Stremio opened and entered the player loading state.
- Attempted manual UI taps on stream chips, but the `StreamActionSheet` did not open via ADB coordinate taps.
- Attempted an integration test, but the unflavored `flutter test integration_test/...` build failed; adding `--flavor full` fixed the build phase before the run was interrupted.
- Reverted temporary pubspec/integration_test changes to keep the working tree clean.
- Moved all verification screenshots from the repo root into `.scratch/wireless-debug/2026-07-11/`; established an artifact-management policy that technical debugging output stays out of source-controlled paths.
- Created `.devin/skills/dart-wireless-debug/SKILL.md` for Devin CLI compatibility.
- Created Ciel-format skill at `~/.ciel/skills/dart-wireless-debug/` (SKILL.md + CHANGELOG.md) and packaged it as `~/.ciel/archive/dart-wireless-debug.skill`.
- Wrote vault notes: concept note and project update documenting the verification, blockers, and next steps.

## Verification

- `flutter analyze --fatal-infos`: 0 issues (ran earlier in session).
- `test/addon/stream_pipeline_e2e_test.dart`: 16/16 tests passed.
- APK install on device: success.
- Stremio player deep link launch on device: success (player opened).
- Full X-Seed UI tap-to-play flow: partial — navigation worked, stream chips did not respond to coordinate taps.

## Blockers / observations

- Flutter apps on this device are invisible to `uiautomator` and `mobile-mcp` element listing, forcing screenshot + coordinate-based automation.
- Coordinate taps on `ActionChip` widgets inside a `CustomScrollView` were unreliable; classified as a repeat-risk failure pattern. Skill now mandates evolution after 3 identical failures.
- X-Seed's `xseed://search?query=...` deep link does not refresh search when delivered to an already-running activity.
- Flavored Flutter projects require `--flavor` and `--target` flags for `flutter test integration_test` to build successfully.

## Next steps

1. Create a dedicated integration test that calls `ExternalPlayerLauncher.launchStremioPlayer` on a real device with a legal torrent.
2. Investigate the `ActionChip` tap issue or add a more automation-friendly entry point for testing the full UI flow.
3. Backfill this diary entry's learnings into the X-Seed `AGENTS.md` known-issues section.
